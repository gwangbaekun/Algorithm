# LeetCode 행 단위 테스트 러너 설계

## 목표

텍스트 파일의 비어 있지 않은 각 행을 하나의 테스트 케이스로 읽고, 문제별 Python 파일에서 모든 케이스를 순서대로 실행해 결과를 터미널에 출력한다.

## 입력 형식

각 행에는 `Solution` 메서드의 매개변수 순서에 맞춰 Python 리터럴 형식의 인자를 쉼표로 구분해 작성한다. 러너는 한 행을 메서드의 위치 인자들로 분리하여 `solution_method(*args)` 형태로 전달한다.

```text
[3,2,2,3], 3
[1,2,3,3,4], 3
```

예를 들어 `removeElement(self, nums, val)`에는 첫 번째 값이 `nums`, 두 번째 값이 `val`로 전달된다. 다른 문제에서도 해당 `Solution` 메서드의 매개변수 개수와 순서에 맞춰 한 행을 작성한다.

공백 행은 무시한다. 입력은 임의 코드 실행을 막기 위해 `eval` 대신 `ast.literal_eval`로 해석한다.

## 구성

- `python/leetcode/test_runner.py`
  - 테스트 파일을 행 단위로 읽는다.
  - 각 행을 위치 인자 튜플로 변환한다.
  - 전달받은 문제별 콜백을 각 테스트 케이스에 호출한다.
  - 케이스 번호, 입력, 실행 결과를 터미널에 출력한다.
- `python/leetcode/leet_test.py`
  - 기존 `Solution`을 유지한다.
  - 현재 문제에 맞는 콜백과 테스트 러너 실행 진입점을 정의한다.
- `python/leetcode/leet_test.txt`
  - 위 형식의 테스트 입력을 여러 행으로 저장한다.

## 책임 분리

공통 러너는 입력 파싱과 반복 실행만 담당한다. 반환값, 변경된 리스트, 기대값 등 문제마다 달라지는 검증 기준은 문제 파일의 콜백이 결정한다. 따라서 특정 LeetCode 문제의 출력 구조를 공통 모듈에 고정하지 않는다.

## 오류 처리

파싱이나 콜백 실행에 실패하면 해당 케이스 번호와 오류를 출력하고 다음 케이스를 계속 실행한다. 한 케이스의 실패로 전체 실행이 중단되지 않는다.

## 확인 기준

- 두 입력 행이 각각 한 번씩 순서대로 실행된다.
- 리스트와 정수 인자가 원래 Python 타입으로 콜백에 전달된다.
- 공백 행은 실행되지 않는다.
- 잘못된 행이나 실행 오류가 어느 케이스에서 발생했는지 터미널에서 확인할 수 있다.
